# 城市应急物资投送完整 Demo

此 Demo 按当前练习场景及已确认的路线实现：起飞 → 识别第一窗口并穿越 → 四点空中抛掷 → 飞向第三点时同步调整机头，投掷第三件物资时远距识别第二窗口 → 飞往第四点时降到穿窗高度 → 抛出第四件物资后沿当前机头方向直接穿越第二窗口、快速返航并降落。不包含裁判、计分或裁判事件声明。

工作区没有完整竞赛规则书，因此这里的完成条件是上述练习流程；识别结果不擅自解释成投放指令，物资顺序通过参数明确指定。拿到正式规则后，可进一步调整动作、限时和识别结果的含义。

## 一条命令运行

先关闭之前启动的 Gazebo、飞控和最小示例。进入实际工作区（包含 scripts、src 的那一层）：

```bash
cd /home/chen-qian/Desktop/demo_delivery_ws/demo_delivery_ws
bash scripts/run_full_demo.sh
```

首次运行会自动编译主程序和投掷扩展。此脚本不运行原来的最小投放示例。默认同时打开 Gazebo 和 RViz，投掷扩展就绪、位姿、雷达及全部物资准备好后任务自动开始。RViz 显示前视相机、识别标注、点云、碰撞箱、橙色计划路线、绿色实际轨迹和当前步骤。任务结束后保留场景用于查看四个物块的落点和飞行轨迹。

重复演示时按 Ctrl+C 关闭整套程序，再执行启动命令。物块已释放后，不能直接在同一场景重跑任务。

无界面运行（仍使用真实 Gazebo 相机）：

```bash
bash scripts/run_full_demo.sh gui:=false rviz:=false
```

启动脚本使用 `PYTHONNOUSERSITE=1`，避开用户目录 NumPy 2 与 Ubuntu OpenCV/cv_bridge 的 ABI 冲突，不修改全局 Python 包。

## 指定投放顺序

点位按 drop_1 → drop_2 → drop_3 → drop_4 固定访问。编号含义为 1=红、2=黄、3=黑、4=白；默认 `1234`。例如黑、红、白、黄：

```bash
bash scripts/run_full_demo.sh drop_order:=3142
```

也可使用 `drop_order:=black,red,white,yellow`。每种物资必须且只能出现一次。不根据 Gazebo 模型名里的旧颜色名称推断点位要求。

识别节点从 `/uav/camera/image` 实际检测：第一窗口使用 ArUco 4x4_50，第二窗口使用官方候选图库的 SIFT 特征匹配和 RANSAC 几何校验，连续三帧一致才确认。支持贴图镜像；检测结果和标注图会保存。识别过程不读取贴图随机结果 JSON 或材质配置。第二窗口的识别范围为随包候选图库，未知的新图片需要补充图库或另换识别模型。

## 路线与控制

| 项目 | 默认值 |
| --- | --- |
| 起降中心 | (3.07, -2.38) |
| 第一窗户中心线 | (1.925, -0.3275) |
| 第二窗户中心线 | (1.925, -2.3725) |
| 四个投放点 | (1.12, -0.15)、(0.02, -0.67)、(0.02, -2.03)、(1.12, -2.53) |
| 第一窗口穿越高度 / 速度指令 | 0.74 m / 0.25 m/s（对应仿真实际速度 0.5 m/s） |
| 第二窗口返航速度指令 | 0.25 m/s（对应仿真实际速度 0.5 m/s） |
| 第一点至第三点抛掷高度 | 1.05 m |
| 第四点抛掷高度 | 0.74 m（直接穿越第二窗口） |
| 巡航 / 投掷航段速度指令 | 0.25 m/s（对应仿真实际速度 0.5 m/s，投掷时持续运动） |
| 全程实际三维速度上限 | 0.5 m/s（包括起飞、同时平移和升降、返航降落） |

控制器订阅 `/flight_control/current_pose`，将世界坐标误差转换到机体坐标，通过 `/flight_control/cmd_vel` 控制；不发送瞬移命令。第一窗口在 1.27 m 高度识别后下降到 0.74 m，沿中心线穿越并留出 0.70 m 机体宽度、脚架及旋翼的净空。按用户补充的比赛限速，全程实际飞行速度上限设为 0.5 m/s；识别结果一旦确认就进入下降对准和穿窗动作，不再增加确认后的悬停时间。

当前仿真实测位移速度约为速度指令的两倍，因此巡航、穿窗、投掷和返航指令统一为 0.25 m/s。发布前按 `max_speed / sim_velocity_gain` 限制三维线速度向量的模长，同时平移和升降也不会叠加超限；角速度、路线、识别和投掷流程保持原设置。`report.json` 分别记录水平峰值 `peak_speed_mps` 和包含升降的三维峰值 `peak_3d_speed_mps`。靠近航点和降落时允许低于上限。

四个释放位置在起飞前计算，补偿物块在托盘中的偏移、投掷高度和水平提前量。提前量随本次降速配套缩短，默认前三次提前约 0.22 m，第四次按较低高度继续缩短，避免盒子相对慢速无人机前冲而碰到托盘。无人机经过释放区时直接发出投掷命令，不减速至悬停、不等待释放确认；确认和落地采样在后台处理。抛出后沿释放方向持续飞行 0.24 秒，让盒子离开托盘及脚架范围，再接入下一航段。这段期间仍持续移动，不是暂停。

投掷扩展调用官方接口松开盒子，并在松开后的物理更新中立即赋予一次水平初速度。初速度由当时物块的释放位置、下落速度与预设目标计算，随后只由 Gazebo 重力、摩擦和碰撞计算轨迹；不更改位姿、不在空中修正方向、不在落地前清零速度。盒子从释放后就具有水平位移，轨迹为抛物线。这个扩展是本 Demo 新增的仿真弹射执行器，官方原始接口只支持松放，没有新增真实机械臂关节。

投掷使用 `/delivery/throw_cmd`，消息为 `唯一标记 颜色 目标x 目标y`，例如 `trial_1 red 1.12 -0.15`。`/delivery/throw_state` 返回 `released`（弹射初始状态）及 `landed`（落地轨迹）。重复标记不会重复释放。普通 `/delivery/drop_cmd` 仍是原地松放接口。导航不读取 Gazebo 模型状态；扩展内部读取物块状态用于计算这一次初速度及记录验证数据。

第二窗口识别请求从第一窗口穿越后就开始。飞向第三点时同步转向，第三次投掷及飞往第四点期间在后台进行相机三帧确认；结果和标注截图保存到报告，不在第三点停下来等识别。飞往第四点前段保持高度，距释放位置 0.55 m 内开始下降到约 0.74 m，给远距识别留出视野。第四次抛掷后保持当前机头方向直接穿越第二窗口并返航，既不重新转向，也不在窗口前等识别。若在全程结束前确实没有识别结果，任务报告会标明识别失败。

这是已知固定场地的航点方案。雷达会检查前向扫掠空间，遇障碍悬停，持续受阻则失败退出；没有实现任意未知场景的自动绕障。位姿、雷达或物资状态中断，以及识别/航点超时，也会停止并保存原因。

可调整参数见 `src/ican_delivery_examples/config/full_demo.yaml`。修改 Python 源码后可直接重启（使用 symlink-install）；修改入口、launch 或资源安装配置后执行：

```bash
source scripts/setup_env.sh
PYTHONNOUSERSITE=1 colcon build --symlink-install --packages-up-to ican_delivery_examples
```

## 查看结果和停止任务

每次运行保存到 `demo_runs/日期_时间/`：

- `report.json`：完成/失败状态、步骤、识别结果、投掷初速度、逐帧抛物线采样、释放前后无人机速度、落点与配置。
- `window_1.jpg`、`window_2.jpg`：识别标注图。

终端出现“完整 demo 完成”且报告 `result` 为 `completed` 表示流程完成。失败退出码为 1。该结果只反映本 Demo 的流程，不代表官方裁判得分。

另开终端可监控或停止：

```bash
source scripts/setup_env.sh
ros2 topic echo /delivery/mission_status --qos-durability transient_local
ros2 topic pub --once /delivery/mission_command std_msgs/msg/String '{data: abort}'
```

停止命令发送零速度让无人机悬停；Ctrl+C 关闭整套仿真。

仿真保持开启时，可对已完成报告做独立的只读物理落点检查（不参与控制、不计分）：

```bash
source scripts/setup_env.sh
PYTHONNOUSERSITE=1 python3 scripts/verify_full_demo.py demo_runs/本次目录/report.json
```

工具检查四个物块实际落地且位于半径 7.5 cm 的内环、报告内四条空中轨迹符合重力抛物线、每次投掷前后无人机持续运动、返回起降点误差小于 3 cm，并核对三维实测峰值未超过配置限速（浮点比较容差 0.000001 m/s），保存 `verification.json`。这是开发验证工具，不是裁判系统。
